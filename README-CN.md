# T-Dash — 开源免费的 Tesla 仪表盘 App（非官方 · BLE-only）

> [English](README-EN.md) | 简体中文

T-Dash 是一款**开源免费**的 Tesla 仪表盘 App（非官方），**纯蓝牙直连**：仪表、控制、统计与
一整套行车工具全部通过 BLE 与车辆直接通信。**T-Dash 没有服务器**：没有开发者账号、没有车主账号登录、没有订阅，
也没有遥测。命令层基于 Tesla 官方开源库
[teslamotors/vehicle-command](https://github.com/teslamotors/vehicle-command)
定义的 Vehicle Security / Infotainment 协议，用 Kotlin 从零实现；`.proto` 定义取自官方仓库。

> **免责声明**：本项目与 Tesla, Inc. 无隶属关系，仅供个人车辆管理与学习使用。
> 使用即表示你理解：向车辆发送指令属于你自己承担风险的操作；驾驶中请勿操作手机，控制结果以车辆本身为准。

## 能力边界（先读这个）

- **手机需在车旁（约 5 m 内）**：所有功能都依赖 BLE 直连；远程控制在当前版本不提供
  （协议层已预留 Fleet API 的 HMAC 授权模式，未启用）。
- 车机屏幕自带的界面无法被第三方 app 绘制；本 app 的「仪表」页是**手机侧**数字仪表。
- 联网只用于三处：统计页轨迹的高德地图瓦片（公开栅格端点，磁盘缓存）、「事故处理 → 我在哪」
  的定位解析，以及可在设置里开启的仪表天气（高德，默认关）。这些请求由手机直接发往
  高德/OpenStreetMap，**不经过 T-Dash**——本项目没有服务器。车辆链路全程 BLE。
- 首次配对需要**实体 NFC 钥匙卡**：发送配对请求后把卡贴在中控读取区，并在车机屏幕确认。
- 兼容性：协议要求车机固件 ≥ 2023.38；命令响应加密需要 ≥ 2024.38（旧固件自动回落明文）。
  手机端要求 Android 10（API 29）及以上，且支持 BLE。
- 开发和测试范围：个人开发项目，只在 Tesla Model 3 焕新版和 vivo X100 上做过实车验证；
  其他车型或机型可能遇到未覆盖的问题，欢迎提 Issue，也可以自行修改源码修复。

## 功能一览

- **仪表（首页）**：大数字车速（按速度分档配色，有没有超速瞟一眼就能发现；口径可与车机对齐）、功率弧、阈值轨、
  档位；P 档切换驻车版面（时钟 + 电量/车外温度/空调卡），行车版面右上角有迷你「时间+天气」；「接续上一段路程」浮层；
  行驶中 D/R 档息屏/后台仍保持监听，P 档自动安静。
- **控制**：锁/后备箱/前备箱/充电口/车窗/空调/充电/哨兵/唤醒/鸣笛闪灯。按钮可用性跟随
  车辆真实状态（已解锁禁「解锁」、行驶中禁开闭件、未插枪禁充电启停）；显示最后一次读到的
  状态而非空白，命令失败原因就地显示，并标出每条命令的实测延迟。
- **工具**：快捷启动（拉起高德等常用 App）、事故处理（定位报址 + 拍照取证清单 + 一键
  导出 A4 取证 PDF）、行车记录仪（读 U 盘 TeslaCam，事件列表、1–4 路同步回放、
  「跳到触发时刻」、2×2 合成导出并烙时间码）、零百计时（250 ms 车速流插值，±0.05 s）、
  车机皮肤（图片压缩写 U 盘 Wraps，车机直接应用）。
- **统计**：车速/功率实时曲线（本会话全量保留）、按速度着色的 GPS 轨迹地图、
  行程切换与叠加、本地 JSON 持久化（崩溃恢复）。
- **设置**：连接兜底（手动 MAC / 自定义广播名）、高德 Key（事故地址翻译与可选天气）、
  速度分档与五段配色自定义（±1 km/h 步进、8 色色板）、事故取证个人信息、
  本机钥匙与缓存管理、开发者模式。

## 使用说明

### 安装与权限

- 安装 Release APK，或按下文「开发者说明」自行构建。系统要求 Android 10 及以上。
- 首次启动会请求蓝牙/「附近的设备」（Android 12+）与**精确位置**权限。Android 12+ 的
  蓝牙扫描在系统层面可以不要位置，但部分 OEM 在缺少精确位置时会返回受限的扫描结果，
  因此本 app 仍然申请；位置只用于本机轨迹、事故定位和可选天气，不上传。
- 读写 U 盘、保存取证照片都走系统文件选择器与 MediaStore，**不需要存储权限**。
- 从未配对成功过时，打开 app 会直接落在「设置」页显示首次引导。

### 首次连接（三步）

1. **站到车旁**：保持约 5 m 内，打开手机蓝牙。在「设置」输入 17 位 VIN
   （见车辆铭牌或行驶证），点「扫描并连接」。
2. **发一次配对请求**：链路显示「已连接」后，点「发送配对请求」。
3. **刷卡并确认**：把 NFC 钥匙卡贴在中控读取区（杯架前方的卡槽），在车机屏幕点「确认」，
   选择车主权限。app 会自动检测结果，最长等待 2 分钟；失败可点「重试」。

配对成功后，本机只把公钥交给车辆，私钥始终留在手机里；之后打开 app 会自动重连。

### 日常使用

- 打开 app 自动连接车辆；仪表页是首页。仪表页和调试页会保持屏幕常亮。
- 从 P 档挂入 R/D 时会自动切到仪表页；不需要再手动点页签。
- 手动点过「断开」后，自动重连不会再把链路拉起，需要点「扫描并连接」恢复。
- 手机离开车旁会断链；回到车旁打开 app 即可。行车中 D/R 档熄屏或退到后台仍保持监听。

### 各页做什么

| 页签 | 内容 |
| --- | --- |
| 控制 | 门锁、前后备箱、充电口、车窗、空调、充电、哨兵、唤醒、鸣笛闪灯；按钮随车辆真实状态可用/禁用，失败原因就地显示 |
| 工具 | 快捷启动、事故处理、行车记录仪、零百计时、车机皮肤 |
| 仪表 | 车速/功率/档位/朝向；P 档驻车版面有时钟、电量、车外温度、空调，启用的天气显示在时钟下方；行车版面右上角有迷你「时间+天气」；本次行程卡与轨迹小图 |
| 统计 | 车速与功率曲线、按速度着色的 GPS 轨迹、行程切换与叠加、删除行程；无网络时底图变灰但轨迹照常绘制 |
| 设置 | 连接、钥匙、高德 Key、速度分档、取证信息、本机数据；开发者模式下额外出现「调试」页 |

**工具页补充**：

- **快捷启动**：目前内置高德地图、支付宝、微信、美团。没装的 App 会直接提示「没找到」。
- **事故处理**：按 1→6 步走（报警、报位置、拍照取证、撤离、报保险等）；照片存到相册
  `Pictures/TeslaLink`，导出 PDF 走系统分享面板。姓名、手机、车牌、保险公司和驾驶证/
  行驶证照片需先在「设置 → 个人信息」里填。
- **行车记录仪**：把 TeslaCam U 盘用 OTG 插到手机，选择 U 盘里的 `TeslaCam` 目录
  （或 U 盘根目录）。对 U 盘只读不写；事件列表按「有加速度/哨兵/手动/滚动」筛选，
  可 1–4 路同步回放、跳到触发时刻，或合成带时间码的单个 MP4 到相册
  `Movies/TeslaLink`。合成要逐帧解码再编码，速度约为实时的 1/2~1/3。
- **零百计时**：待命后从静止起步自动开表，到 100 km/h 停表；待命 120 s 未起步、
  起步 60 s 内未到 100 会自动作废。仅限封闭场地使用。
- **车机皮肤**：U 盘根目录的 `Wraps` 目录，正方形 PNG、边长 512–1024、单张 ≤1 MB、
  最多 10 张；非 1:1 会先裁切，超过 1 MB 自动压缩。应用时把 U 盘插回手套箱，
  在车机「玩具箱 → 喷漆车间 → Wraps」选择。删除会真删 U 盘文件（二次确认），
  但不会动 TeslaCam 里的记录仪数据。

### 设置项说明

- **连接兜底 → 车辆 BLE 地址（MAC）**：用 nRF Connect 在车旁能看到车辆（名称形如
  `S…C`）而本 app 扫不到时填写；保存后跳过扫描直接拨号。「自定义 BLE 广播名」只影响
  本 app 的匹配，不是车辆昵称。
- **高德 Key（通用）**：只影响「事故处理 → 我在哪」的地址翻译和可选的仪表天气；
  统计页底图不需要 Key。去高德开放平台申请 **Web 服务**类型的 Key，只填 Key 本身，
  不需要「安全密钥」，也不要勾选数字签名。平台选错会报 10009；未配置时地址翻译退回
  OpenStreetMap（国内常常连不上）。
- **仪表天气**：默认关。开启后需要已保存 Key 和位置权限；用手机最近一次定位
  查城市再取天气，约 30 分钟一刷，行车中照常取（走手机网络，不发蓝牙请求、不占车机链路）。
  驻车版面显示在时钟下方，行车版面显示右上角迷你「时间+天气」。任何一步失败都整块不显示，
  不放占位符——行车版面此时只显示时间。
- **仪表速度分档**：默认 66 / 88 / 110 / 132 km/h，相邻两档至少差 1；改动立即生效，
  大数字、光晕和阈值条一起换色；可恢复默认。
- **个人信息（事故取证用）**：只被取证 PDF 读取，文字进 DataStore，证件照复制进应用
  私有目录，都不出本机。
- **本机钥匙与缓存**：显示钥匙指纹末四位。只有调试页提示「本机钥匙无法解密」时才需要
  重新生成；这会换掉本机钥匙，之后必须重新刷卡配对，并在车机「控制 → 钥匙」删除旧条目。
  日常更新 app、重启手机都不会换钥匙。「协议会话缓存」用于加速首条命令，持续报签名/
  计数器错误时清除重建。
- **开发者模式**：打开后底栏出现「调试」页；日常使用无需开启。

### 常见问题

- **扫不到车辆**：① 官方 Tesla App 可能占用了车辆的 BLE 连接（上限 3 个），请完全退出它；
  ② 车辆唤醒或行驶中 VCSEC 可能不再广播，先锁车等 2–3 分钟再试；③ 检查系统是否只给了
  「附近的设备」而拒绝了位置权限（部分国产 ROM 会因此返回受限扫描结果）；④ 用 MAC 兜底。
- **配对失败**：确认卡片贴在读取区、车机屏幕点了「确认」并选择车主权限；2 分钟超时后
  直接重试。固件低于 2023.38 时协议不兼容。
- **控制没反应或很慢**：先看设置页链路状态；车在休眠时需要先唤醒，首条命令会多一次往返；
  手机离车太远、或车辆正在被官方 App 连接都会影响时延。控制页会显示每次命令的实测毫秒数
  和失败原因。
- **天气不显示**：确认设置里天气已开、Key 为 Web 服务类型、已授予位置
  权限且有网络。驻车版面看时钟下方，行车版面看右上角迷你组件（天气不可用时迷你组件仍显示时间）。
  上述任一不满足时整块不显示是有意设计，不是占位缺失。
- **地址只有坐标**：高德 Key 缺失或平台不对（常见 10009）；OSM 兜底在国内多数网络下不可达。
- **记录仪扫不到/播不了**：确认 U 盘里有 `TeslaCam/RecentClips`、`SentryClips`、`SavedClips`；
  拔插过 U 盘要重新授权目录；「重新扫描」只重列当前目录，不重新选择。
- **统计页没有轨迹**：轨迹在「仪表」或「统计」页、车速 > 2 km/h 时记录；需要位置权限。
  室内 GPS 漂移点会被过滤，但不代表能替代专业记录设备。
- **换手机、卸载重装或清除数据**：本机钥匙会丢，必须重新配对，并在车机「控制 → 钥匙」
  里删除旧条目，避免钥匙列表越积越多。

## 延迟为什么低

| 通道 | 典型延迟 | 依赖 |
| --- | --- | --- |
| **BLE 直连（唯一通道）** | **~50–300 ms** | 无 |

- **会话缓存**：握手结果（epoch/counter/域公钥）落盘，重启后首条命令省一次往返。
- **VCSEC 免唤醒**：锁车/解锁/门锁状态走车身安全控制器，整车休眠也秒回。
- **行驶期带宽分配**：车速道独占快路径（250 ms，单次尝试短超时），慢车道在行驶中静默，
  慢路径失败不阻塞车速。
- 控制页显示每条命令的实测毫秒延迟。

## 开发者说明

### 环境要求

- **JDK 17**（`compileOptions` / `jvmTarget` 均为 17）。
- **Android SDK Platform 35** + **Build-Tools 35.0.1**；`compileSdk 35`、`targetSdk 35`、
  `minSdk 29`。
- Android Studio 最新稳定版即可；纯命令行构建也可以。
- 版本由 `gradle/libs.versions.toml` 统一管理：AGP 8.13.0、Kotlin 2.2.20、
  Compose BOM 2024.12.01、protobuf 4.29.3。
- 在项目根目录创建 `local.properties` 并写入本机 SDK 路径（该文件不入库）：
  ```properties
  sdk.dir=C\:\\Users\\<you>\\AppData\\Local\\Android\\Sdk
  ```
- Gradle Wrapper 使用 8.13，发行包走腾讯镜像；依赖仓库在 `settings.gradle.kts` 里配置了
  阿里云镜像，海外环境可自行改回 `google()` / `mavenCentral()`。

### 构建与单测

```bash
./gradlew :app:assembleDebug        # 产物：app/build/outputs/apk/debug/
./gradlew :app:installDebug         # 安装到已连接设备
./gradlew :app:testDebugUnitTest    # 协议测试向量 + 行程持久化等 JVM 单测
./gradlew :app:assembleRelease      # 需要签名配置，见下一节
```

首次构建会由 protobuf 插件下载 `protoc`，并从 `app/src/main/proto/` 生成 lite 版 Java
绑定（生成物在 `build/` 下，不要手改）。

### 发布签名

发布签名只从根目录的 `keystore.properties` 读取，该文件和 `*.jks` / `*.keystore`
都已被 `.gitignore` 排除，**不要提交**：

```properties
storeFile=../release.jks
storePassword=...
keyAlias=...
keyPassword=...
```

- `storeFile` 按 `app` 模块目录解析，写绝对路径也可以。
- 没有该文件时 `release` 构建不会挂签名配置，产物为未签名 APK；日常调试用 `assembleDebug` 即可。
- `versionCode` / `versionName` 在 `app/build.gradle.kts`。当前版本文案另有硬编码：
  `SettingsScreen.kt` 的「关于」区和 `promo/index.html` 页脚，发版时三处一起改。

### 协议实现与测试

- `app/src/main/proto/` 下的 `.proto` 取自 `teslamotors/vehicle-command`，构建时生成
  `*OuterClass` 等 lite 绑定。
- 协议核心在 `protocol/`：`Crypto.kt`（P-256 ECDH、AES-GCM、HMAC-SHA256）、
  `Session.kt`（命令签名/响应解密、会话导出恢复）、`Dispatcher.kt`（会话管理、
  请求-响应匹配、缓存与重同步）、`Metadata.kt`（TLV）、`Errors.kt`（错误分类、
  重试判定、防重放滑动窗口）。
- `app/src/test/` 是不需要真车的回归网：`ProtocolVectorsTest` 移植官方测试向量
  （ECDH/HMAC/TLV/GCM 等），另有行程落盘、漂移过滤、续接等用例。改协议或加密代码后
  必须先让 `:app:testDebugUnitTest` 全绿。

### 开发约定

- **车辆链路只走 BLE，项目不建服务器**。`INTERNET` 只允许用于统计页底图、定位解析和
  可选天气，由手机直发第三方；不要把车辆命令、遥测或轨迹转发到任何服务器，也不要引入
  自建后端、账号体系或遥测/崩溃上报 SDK（`CrashLog` 只落本机）。新增联网点要同步更新
  README 的安全与隐私说明、设置页「关于」和宣传页的联网描述。
- **权限姿态不要“清理”**：`BLUETOOTH_SCAN` 故意不声明 `neverForLocation`，
  Android 12+ 也仍然申请 `ACCESS_FINE_LOCATION`——部分 OEM（如 OriginOS）在
  `neverForLocation` 下会返回受限扫描结果，可能完全看不到车辆广播。改动前先读
  `AndroidManifest.xml` 里的注释。
- **新增快捷启动 App**：Android 11+ 包可见性要求同时在 `AndroidManifest.xml` 的
  `<queries>` 里声明包名，并在 `ToolsScreen.kt` 的快启列表里加一项；否则
  `getLaunchIntentForPackage` 返回 null，表现是“点了没反应”。
- **高德 Key 只做运行时输入**：保存在本机 DataStore（`amap_key`），不要写进源码、
  `BuildConfig` 或日志。天气默认关；没 Key、没定位权限或请求失败时整块不显示，
  这是产品决定，不要改成占位符。
- **删除操作不得碰用户文件**：取证照片的「移除/清空」只动页面清单，不删相册原图；
  记录仪对 U 盘只读；皮肤工具只操作 `Wraps` 目录，绝不触碰 `TeslaCam`。
- **日志**：新增日志不要打印私钥、Keystore 密码、用户高德 Key；密钥只允许出现指纹末四位。

### 调试

1. 「设置 → 关于与开发者」打开**开发者模式**，底栏出现「调试」页（该页保持屏幕常亮）。
2. 「开始自检」串跑 9 步：VCSEC 会话、钥匙链、本机公钥在册、车机握手、唤醒、车机重试、
   Ping、单类遥测、全类遥测，约 1 分钟，故障码全部落日志。
3. 排障时可打开「协议收发」记录每条 BLE/协议报文与帧 hex（轮询时会刷屏，平时关掉）。
   日志支持按 tag 过滤、复制全部、清空。
4. 上次异常退出会在调试页顶部还原崩溃现场，可一键复制；`debug/CrashLog.kt` 负责落盘，
   崩溃日志按需在「知道了」后清除。
5. 没有实车时，协议与行程逻辑全部可用 JVM 单测覆盖；BLE 行为需要真车，可配合
   nRF Connect 核对车辆广播名与 MAC。

## 安全与隐私：T-Dash 没有服务器

**T-Dash 没有服务端。** 项目不运营任何应用后端、API 端点、中继或云同步：没有账号体系，
没有遥测上报，也没有可供开发者查询用户数据的管理后台。手机与车辆之间只有 BLE 直连，
因此不存在集中存放车主数据的数据库或接口，也没有可被远程攻破的项目服务端。

- **钥匙不出手机**：私钥（P-256）由 AndroidKeyStore 加密后仅存本机；配对只把公钥交给车。
  开发者和任何服务器都拿不到私钥。
- **数据不出手机**：行程轨迹、个人信息、协议会话缓存和崩溃日志存在应用私有目录，
  卸载或清除数据后随之消失；取证照片在系统相册 `Pictures/TeslaLink`，导出视频在
  `Movies/TeslaLink`，由系统相册管理，卸载 app 不会自动删除，需要你自己清理。
  app 内的删除操作不会主动删这些相册文件。
- **联网不经过 T-Dash**：只有统计页底图、定位解析和可选天气会出网，且由手机直接发往
  高德或 OpenStreetMap（未配置 Key 时定位解析退回 OSM）。发出的只有瓦片编号、坐标或
  城市编码，不含 VIN、车速或轨迹文件；请求不经过本项目控制的任何端点。
- **无遥测、无账号、无云端**：app 不要求登录，不接入 Tesla 账号，也没有“上传诊断”
  这类开关；调试日志只在手机本地查看和手动复制。
- **日志最小化**：日志只出现密钥指纹末四位。
